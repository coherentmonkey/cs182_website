Special Participation B: Gemini (Thinking With Pro 3) on HW08

By Nicolas Rault-Wang 2025-11-26 HW8 Gemini
View on Ed Stem →
I used Gemini (Thinking with Pro 3) to solve every coding question of homework 8. Here's the PDF summarizing our interaction: Overview of Performance I used Gemini (acting as a Teaching Assistant/Technical Solver) to solve the coding portion of Homework 8 (only Q2: SSM Forward Passes). I constrained Gemini's behavior with strict protocols for self-correction, variable mapping to ground its context, and state-machine interaction rules to focus its attention single well-defined subtask. Gemini successfully implemented PyTorch solutions for the CPU and GPU State Space Model notebook in total of 6 prompts (including role definition prompts). While it generated syntactically correct code for the base cases immediately, I needed to follow up to correct an oversight regarding computational complexity (in the CPU notebook) and debug a shape-mismatch error in the diagonal optimization task (in the GPU notebook). Interestingly, Gemini thought for significantly longer on average during this interaction compared to usual. Each time I uploaded a code notebook, Gemini spent about 3 minutes thinking before it responded. When I asked Gemini about why it took so long, it said that my prompts forced it to think harder about details and use more computationally expensive tools like its code environment and internal search tools to double check and cross reference its work. Overall I'm very impressed at how quickly Gemini solved the entire problem. These models are getting scarily competent. Outcomes One-Shot Success Rate: ~66% High Success: Translating algorithms to code: Gemini successfully converted the mathematical definitions of SSMs (recurrence vs. convolution) into functional PyTorch code. Structure preservation: Correctly parsed the uploaded Jupyter notebooks to use the exact variable names and function signatures required by the autograder. I believe the staged problem solving protocol of first extracting variable mappings then writing code helped Gemini not hallucinate (though I could be wrong). Lower Success: Complexity analysis: Initially, Gemini claimed the convolution method was strictly faster on CPU. I had to prompt it to re-evaluate the cost of generating the kernel ($O(H^3)$), which prompted it to reevaluate and recognize the discrepancy. Broadcasting logic: In the diagonal optimization question (Q2f), the model initially wrote code that caused a RuntimeError due to a dimension mismatch (treating a diagonal matrix as a 2D tensor instead of a 1D vector). I had to provide the error trace to help it debug. Hallucinations: Zero hallucinations. Interactive debugging: When the diagonal implementation failed the sanity check, I provided the Python error trace. The model successfully analyzed the traceback, identified the broadcasting error, and patched the code in its next response without needing further hints.
