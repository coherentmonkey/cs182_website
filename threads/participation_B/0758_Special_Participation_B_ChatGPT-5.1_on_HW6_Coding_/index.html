Special participation B: ChatGPT-5.1 on HW 6 Coding questions. There were five ipynb files in Hw6’s coding assignment. I kept each question in a separate ChatGPT-5.1 tab to maintain better context within each conversation. For GPUMemory.ipynb, there was nothing to modify other than running cells and looking at the output, so it didn’t make sense to run this through an LLM. For q_coding_muon.ipynb, the LLM initially assumed X was square, and wrote code accordingly: ``` for _ in range(num_iters): # Newton–Schulz cubic orthogonalization step: # X <- (3X - X^3) / 2 X3 = torch.matmul(X, torch.matmul(X, X)) X = (3 * X - X3) / 2 ``` However, these dimensions led to: RuntimeError: mat1 and mat2 shapes cannot be multiplied (32x27 and 32x27) Upon telling the LLM about this, it revised its answer to: ``` for _ in range(num_iters): # Implement X^3 in a way that works for rectangular X: # X^3 ≈ X (X^T X), which has the same effect on singular values X3 = X @ (X.mT @ X) # Newton–Schulz cubic step: X <- (3X - X^3) / 2 X = (3 * X - X3) / 2 ``` The resulting code was as expected. Link to the conversation: https://chatgpt.com/share/69389a42-a1f4-800f-88ab-7494a9f6a2b3 Annotated Trace: Q_zkc.ipynb: Was able to one-shot quite well; I am not surprised by this because the questions are set up nicely from a pedagogical perspective, with “fill in the blank” style code sections throughout. It was also able to answer the question about the plots and respond thoroughly to my follow up questions. Link to the conversation: https://chatgpt.com/share/69389a5c-21c0-800f-98aa-9d10cd9eb451 Annotated Trace: Tensorboard.ipynb: Similar to as in the q_coding_muon.ipynb, the LLM had difficulty with matching dimensionality. I dropped in the one-shot code it suggested, and upon calling run() I got: RuntimeError: mat1 and mat2 shapes cannot be multiplied (12288x32 and 3072x2048) This error is more drastic than the previous matmul mismatch. I asked ChatGPT-5.1 to fix its error, and it realized that it needed to first flatten the images. I then pasted and ran the new code, which revealed some other small errors that I had to rerun through the LLM. I asked it also specifically for hyperparameter suggestions, and it returned some more code that did indeed yield better results than the initial 2-epoch run. More info in the trace. Link to the conversation: https://chatgpt.com/share/69389a70-db80-800f-9d6f-4593965786b7 Annotated trace: Wandb.ipynb: Upon pasting the first output from ChatGPT-5.1, i ran into an AttributeError, because in ResNetClassifier it defined an init function, first calling super().__init() Which was interpreted incorrectly. Upon asking ChatGPT-5.1 what this was about, it discovered its error and recommended me to change it to the correct version, super().__init__() However, this attribute error is stemming from architectures.py, which I did not modify. Fixing these, and paying attention to the LLM’s response about when to resize the images, I was able to get a satisfactory result that ran on wandb, though both test and train accuracies weren’t that high after 3 epochs (~61%).
