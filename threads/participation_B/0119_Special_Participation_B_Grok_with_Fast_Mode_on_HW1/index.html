In fact, the snippets themselves are a bit buggy, but I’m including the file here for transparency): https://drive.google.com/file/d/1mH2D93vh20FGKXsGpTb_HLfnXEA5kC3x/view?usp=sharing Executive Summary For Grok, the model generally does well on simple coding questions. I can imagine many people have already asked it similar questions for solving deep learning class problems (e.g., Stanford or elsewhere). The methods here—GD and GD with momentum—aren’t new concepts, so the LLMs were likely trained on them. Grok one-shotted most of the answers and got the main ideas correct. For Question 2, it successfully generated code to make GD with momentum converge faster. However, the issue is that it doesn’t behave like a human would. A human would likely just copy the code from the previous part, tweak the parameters, and test whether the model converges faster. Instead, Grok wrote entirely new variables for this purpose. Both approaches work, but because Grok introduced new variables, the later graph-comparison code failed—since it reused the original inefficient parameters instead of the updated ones. This likely happened because I didn’t include the later code. From a human perspective, we would only read what comes before the question, not anything beyond it yet. On the positive side, there were no hallucinations.
